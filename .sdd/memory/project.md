# Adaptive SDD

## Purpose

Help diverse projects use proportionate specification ceremony while preserving resumable, attributable delivery evidence and an optional portable description of the repository over its lifecycle.

## Current capabilities

- Guides TinySpec, LiteSpec, and official GitHub Spec Kit through explicit approval gates.
- Installs one shared skill for Codex and Cursor discovery.
- Scaffolds and validates TinySpec and LiteSpec artifacts deterministically.
- Provides OKF-compatible Project Memory scaffolding, status, validation, and reconciliation mechanics.
- Tracks resumable delivery state with fingerprint-bound approvals, explicit authorization boundaries, tasks, evidence, verification, and release references.
- Offers Guided, Collaborative, and explicitly opted-in Delegated interaction modes independently of specification depth.
- Supplies optional application, API/library, AI-system, data-pipeline, infrastructure, and research/design/documentation profiles.
- Selects optional project-local engineering skills by phase and project profile while retaining Adaptive SDD's artifact, approval, evidence, and memory rules.
- Provides local installation diagnostics and deterministic workflow safety evaluations.

## Boundaries

- Official Spec Kit remains upstream-owned.
- Installing Adaptive SDD does not automatically create specifications or Project Memory in a target repository.
- Agent-produced knowledge requires review before it is marked human-verified.
- Structural validation does not prove implementation or test execution; delivery state is an audit aid rather than authentication or tamper-resistant proof.
- Live agent, marketplace, and upstream Spec Kit compatibility require separately recorded integration evidence.
- Optional engineering skills may advise or execute bounded work, but cannot create a competing specification workflow, expand authorization, or count as delivery evidence merely because they were selected.
